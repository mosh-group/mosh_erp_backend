MOSH ERP — R31 — تكنولوجيا المعلومات ومرفقات محادثة المهمة
الأساس: حزمة R30 المسلّمة سابقاً. المشروعان كاملان؛ لا توجد migrations جديدة.

مهم قبل التركيب
================
هذه الدفعة تغيّر الخلفية والواجهة معاً؛ لا يكفي تبديل الواجهة كما في R30.
لا تكتب قاعدة الحزمة فوق قاعدة السيرفر. الحزمة تحتوي بيانات المصدر المرفوع،
ولا تتضمن تلقائياً ما أدخلتموه لاحقاً. حافظ على قاعدة العمل و.env وAPP_KEY
وstorage والمرفقات وvendor وconfig.js الحالية. خذ نسخة متسقة من SQLite
مع إيقاف الكتابة، ولا تنسخ ملف sqlite منفرداً أثناء كتابة WAL/SHM عليه.

خطوات لمسؤول السيرفر
=====================
1. احتفظ بنسخة احتياطية متسقة من بيئة التشغيل، واختبر التحديث في نسخة منفصلة.
2. الحزمة كاملة بالجذرين MOSH_LARAVEL_BACKEND وMOSH_VANILLA_FRONTEND.
3. R31_CODE_MANIFEST.json يحدد ملفات الكود الجديدة والمعدّلة وبصماتها؛ انقل
   الكود إلى نسخة الاختبار مع إبقاء بياناتها وإعداداتها المناسبة. لا تنقل
   قواعد قديمة أو config.js تجريبي فوق إعدادات السيرفر الحقيقية.
4. استخدم PHP 8.5 وملحقات المشروع اللازمة. ملفات vendor وComposer لم تتغير.
   إذا كانت المسارات مخزنة مؤقتاً، يمسح مسؤول السيرفر كاش المسارات والعرض
   والإعدادات بالطريقة المعتادة، ثم يعيد تحميل PHP/OPcache. لا تعطل CSRF.
5. بعد النجاح اختبر على حساب محدود وحساب مدير، ثم انقل الكود مع إبقاء
   قاعدة الإنتاج الحالية. يُفترض ظهور R31 قرب الشعار بعد تحديث الصفحة.
6. لا تستخدم migrate:fresh أو db:seed أو key:generate أو composer update.
   لا تُشغّل اختبارات PHPUnit العامة أو خادم الاختبار على بيانات العمل.

1 — مرفقات محادثة المهمة
=========================
الرفع الجديد يجزّئ الملف إلى أجزاء 256 كيلوبايت، يتحقق من SHA-256 والحجم
النهائي، ثم يمرر الملف المكتمل إلى مخزن المرفقات الخاص نفسه. الحد الأقصى
25 ميغابايت للمرفق الواحد. بقيت قواعد الامتدادات والصلاحيات مطبّقة.
يعرض تقدم الرفع، ثم ينتظر تأكيد ربط الملف بالمهمة. لا تُضاف رسالة وهمية
عند رفض حفظ المهمة. إعادة المحاولة تستخدم نفس مفاتيح الملف والطلب؛ لا
تنشئ مهمة جديدة. لا تُعاد نافذة أغلقها المستخدم ولا تُمسح مسودة رسالته
عند اكتمال الرفع؛ يتحدث خيط المحادثة المفتوح فقط.
الرفع المجزأ لا يحتاج مجلد PHP multipart المؤقت، لكنه يحتاج مساحة وحق
كتابة في storage/app/private. إذا رفض الخادم حتى طلباً بحدود 350 كيلوبايت
أو منع JSON/PUT، أو كانت المساحة/الصلاحيات غير سليمة، تظهر رسالة تحتاج
معالجة إعدادات الاستضافة. لم يُثبت السبب الدقيق لكل فشل على سيرفرك.
الأجزاء المؤقتة تنتهي بعد 24 ساعة ويُجرى تنظيفها عند بدء رفع لاحق للمستخدم.
انتهاء جلسة المتصفح أو الخروج يوقف الاستمرار بالرفع ولا يحفظ باسم حساب آخر.

2 — القسم الجديد: تكنولوجيا المعلومات IT
=========================================
قسم أصلي بالقائمة وبخيارات الموظف والمهمة وخريطة مدراء الأقسام، مع المهام
الجارية والتوزيع والاعتماد عبر نظام المهام الموجود، وليس نظاماً منفصلاً.
التبويبات: لوحة القسم، المعدات والعهد، حسابات الشركة، الاشتراكات، مهام القسم.

المعدات: رمز داخلي وتصنيف وموديل ورقم تسلسلي ومواصفات ومكان وتاريخ شراء
وضمان وحالة ومرفقات وسجل صيانة وإسناد لموظف وتاريخ إجراءات وأرشفة/استعادة.
الجهاز الجديد ينعكس بعهد موظفه بمصدر it31 محمي من التعديل العام بملف HR.
الأصل المرقم الموجود بالمستودع يمكن ربطه دون إنشاء عهدة ثانية؛ حركات
المستودع تبقى المصدر لتسليمه واسترجاعه. لا يُسمح بأرشفة جهاز بعهدة موظف.
العهد اليدوية القديمة لا تُرحّل تلقائياً؛ الرقم التسلسلي المتكرر يُوقف
إنشاء عهدة جديدة لحين مراجعة الربط، دون حذف أو تعديل السجل القديم.

حسابات الشركة: الخدمة والرابط واسم المستخدم/الإيميل والمسؤول والقسم
وبريد الاسترداد وحالة التحقق بخطوتين والحالة والمرفقات وسجل الإجراءات.
الأرشفة/إيقاف السجل داخل موش لا يوقف الحساب لدى مزوده الخارجي تلقائياً.

الاشتراكات: الموقع والباقة وحساب الشركة المرتبط والرخص والمستفيدون
والكلفة والعملة ودورية الدفع وتاريخ البداية/الانتهاء والتجديد التلقائي
لدى المزود وعدد أيام الإنذار. سجل للتجديدات وأرشفة واستعادة وإيقاف إداري.
التنبيهات داخل لوحة IT عند فتحها/تحديثها؛ لا إرسال بريد أو SMS بالخلفية.
تظهر أيضاً عهد وحسابات الموظفين غير النشطين لمتابعة إخلاء الطرف يدوياً.
تسجيل التجديد أو الإلغاء ليس تنفيذاً أو دفعاً تلقائياً بالموقع الخارجي.

3 — صلاحيات خزنة كلمات سر الشركة
=================================
من لوحة المستخدمين والصلاحيات، ضمن «تكنولوجيا المعلومات وخزنة الشركة»:
- IT — إظهار ونسخ كلمات سر حسابات الشركة (viewITSecrets).
- IT — إدارة حسابات الشركة وتحديث أسرارها (manageITAccounts).
يلزم أيضاً دخول IT وعرض القوائم/التفاصيل والصلاحيات التشغيلية المناسبة.
صفة مدير IT أو مدير نظام وحدها لا تمنح كشف الأسرار. الحساب التقني الأعلى
يحتفظ بصلاحياته. لم تُمنح الحسابات القديمة صلاحية جديدة تلقائياً.
الأسرار في سجل خاص منفصل ومشفر باستخدام APP_KEY؛ لا تظهر في bootstrap
أو ملف الموظف أو قائمة الحسابات أو سجل التدقيق أو استجابة الحفظ.
الكشف يحتاج كلمة مرور حساب موش الحالي وتُسجل محاولة الكشف وصاحبها فقط.
العرض ينمسح بعد 30 ثانية أو إخفاء الصفحة أو الخروج. النسخ إجراء صريح؛
لا يُفترض أن التطبيق يستطيع مسح حافظة نظام التشغيل بعد النسخ.
كلمة سر دخول MOSH نفسها لا تُعرض ولا تُسترجع.

HTTPS إلزامي للخزنة
====================
رابط HTTP الحالي لا يصلح لإرسال أسرار حسابات الشركة أو عرضها. خزنة الأسرار
تحجب الحفظ والكشف دون HTTPS؛ باقي سجلات IT تعمل وفق صلاحياتها. يلزم رابط
HTTPS موثوق للواجهة والخادم مع إعداد صحيح للجلسة/CORS والوكيل العكسي.
لا تعطل التحقق الآمن أو CSRF. أبق APP_DEBUG=false في الإنتاج، ولا تسجل
أجسام طلبات/ردود الخزنة في البروكسي أو أدوات المراقبة. احفظ APP_KEY ونسخة
قاعدة البيانات بأمان؛ فقدان المفتاح يمنع فك أسرار الخزنة المحفوظة.
لا ترسل كلمات مرور حقيقية في هذه المحادثة ولا تضعها في حقل الملاحظات.

الفحص والحدود
==============
9,146 ملفاً أصلياً محفوظاً دون حذف؛ 8,615 ملفاً محمياً مطابقاً.
فحص صياغة 135 PHP و88 JavaScript. قواعد SQLite: 4 سليمة بنيوياً.
54 تحققاً لتجميع الملفات على مساحة فعلية، و26 للصلاحيات ومكون التشفير.
33 تحققاً للواجهة الجديدة/بروتوكول الرفع، و42 للقوائم والمظهر، و45 رجوعياً
للواجهة السابقة، و61 اختبار JavaScript و228 تحقق قواعد سابقاً.
تم نقل ثلاثة ملفات بأحجام مختلفة بينها 5 ميغابايت فعلياً عبر HTTP محلي،
مع حد PHP POST مقداره 1 ميغابايت، وتطابقت بصماتها. حفظ سجل المهمة وIT
في هذا الاختبار كان API محاكاة، لا قاعدة بيانات Laravel حقيقية.
اختبار 25 ميغابايت كان على ChunkStorage بمساحة اختبار فعلية.

لم يكتمل تشغيل Laravel هنا: المصدر يشترط PHP ^8.5 والمتاح 8.4.24 مع نقص
pdo_sqlite وDOM/XML وmbstring وbcmath. لم نعدل vendor أو متطلبات المنصة
لإخفاء ذلك. لا يوجد اختبار جلسة/CSRF/SQL متكامل أو تفويض Meta أو بصمة
حقيقية، ولا نشر على سيرفر الشركة. ليست الحزمة شهادة أن كل النظام مضمون.
تنبيه جلسة «لا يوجد عمل» القديمة والبلاغات خارج نطاق الدفعة لم تُصفّر
ولم تُعدّل بياناتها ولا تُعتبر محلولة تلقائياً بسبب هذا التحديث.

قبول نسخة الاختبار قبل بيانات الإنتاج
========================================
دخول مدير وموظف محدود؛ ظهور قسم IT فقط حسب الصلاحية؛ تعيين مدير IT وموظف
ومهمة واستلامها وحفظها وإعادة الدخول. حفظ معدات وتسليم/نقل/استرجاع وصيانة
وعهدة مرتبطة بالمستودع. تسجيل/أرشفة/استرجاع حساب واشتراك وتجديده.
باستخدام حسابات اختبار فقط وعلى HTTPS: امنح/اسحب كل صلاحية للخزنة منفصلة،
وجرّب رفض كلمة مرور خاطئة ورؤية السجل وعدم تسرب كلمة السر في طلبات القائمة.
جرّب من جهاز الموظف نفسه إرفاق ملف صغير و5 ميغابايت وعدة صور في المحادثة،
ثم أعد تحميل الصفحة وافتح المرفقات؛ جرّب فقدان الاتصال أثناء الحفظ وإعادة
المحاولة دون إنشاء المهمة مرة أخرى. لا تستعمل أسراراً أو مرفقات عميل للاختبار.

ملفات المراجعة: R31_QA.json وR31_CODE_MANIFEST.json وtests/R31.
زرا إلغاء التاسك وتحويله للأرشيف ما زالا مستبعدين حسب قرارك.
